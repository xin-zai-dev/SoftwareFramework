# 无硬件仿真控制台

使用本工程的 `simulated` 后端即可联调相机、运动、光源、PLC 与数字 I/O，不需要厂商 SDK。左侧导航的“仿真控制台”在设计模式和发布后的客户运行模式中均可使用。控制台只列出仿真设备；真实 Modbus 设备不在这里操作。

## 启动

Mac 双击工程根目录 `启动无硬件仿真.command`，或者在 Qt Creator 打开 `CMakeLists.txt`，选择 Qt 6 Desktop Kit，构建并运行 `IndustrialVisionStudio`。默认工程已经包含五类仿真设备。

独立的 `examples/simulation-only.ivproj` 将触发明确路由到 `plc-1`，结果输出路由到 `io-1` 的 holding 地址0，适合按下述步骤联调。可使用启动参数：

```text
--project <工程路径>/examples/simulation-only.ivproj --workspace <工程路径>/simulation-lab --simulation-console
```

首次运行会在指定 workspace 创建 SQLite 数据库、图像与日志。测试数据与源代码保留在本工程目录内。原有工程省略输出 `deviceId` 时选择设备列表中首个 PLC/I/O；默认内置工程因此输出到 `plc-1`。

## 先跑通一件

1. 在控制台关闭“自动触发”。保持流程控制模式，光源 CH1 默认打开、亮度80。
2. 点击顶栏“单次检测”。流程停在等待触发节点，界面仍可操作。
3. 选择 `plc-1`，点击“触发一件”。排队的一次触发被消费，随后执行定位、开灯、采图、测量、判定、保存、输出。
4. 在“实时工作台”查看本次记录、图像和曲线；在控制台选择信号设备 `io-1`，查看 holding 地址0。1表示OK，2表示NG。
5. 在“历史数据”查看已保存记录。图像保留取决于工程的图像策略。

示范工程的等待触发超时为60秒；超时后显示故障，重新点击运行即可再次等待。“连续运行”按工程节拍循环；每点击一次“触发一件”增加一个触发额度，最多排队1024个。DI0保持打开也能放行检测，它是电平条件，持续高电平会在连续模式下重复放行。

## 手动调试轴与光源

勾选“手动接管”后，流程中的运动与光源节点保留控制台状态。未勾选时，每件产品经过这些节点都会重新应用节点参数，适合验证流程命令。

- 每台运动设备包含4轴，轴号0..3。可使能、填写目标位置和速度、点动、定位、回零、停止；实际位置按经过时间变化。默认软限位为−100..100 mm，速度单位mm/s。运动节点等待对应轴到位后才继续。
- XY轴分别影响图像中工件的水平、垂直偏移，工程 `pixelsPerMm` 决定位移映射。Z/R轴保留独立位置状态，用于测试命令与流程等待。目标超出软限位会报错。
- 每台光源包含4通道，通道号0..3，亮度0..255。相机默认读取首台光源的CH1（通道0）。亮度80保持示范曝光；关闭或大幅降低该通道亮度会导致图像测量故障。其他通道保留独立状态，可通过相机参数 `lightChannel` 指定参与成像的通道。
- 改变X/Y位置后跑一件，查看偏移字段和散点图；关闭CH1再跑一件可验证无光故障。恢复光源后需要手动重新启动。

相机默认使用首台仿真运动/光源，也可在设备参数中明确绑定：

```json
{"motionDeviceId":"motion-1","lightDeviceId":"light-1","lightChannel":0}
```

引用不存在、类别不符或断线的设备会返回错误。位移过大可能让工件超出视野，从而造成测量失败或被截断的测量值；该场景可以用来测试应用对异常图像的处理。

## PLC 与 I/O 信号

每台仿真 PLC/I/O 都有独立的四张表，地址从0开始：

| 表 | 控制台含义 | 地址 | 数值 |
|---|---|---|---|
| discrete | DI 数字输入 | 0..15 | 0/1 |
| coil | DO 数字输出 | 0..15 | 0/1 |
| holding | 保持寄存器 | 0..63 | 0..65535 |
| input | 输入寄存器 | 0..63 | 0..65535 |

控制台允许强制输入和输出，寄存器按16个地址分页。运行中的输出节点会再次写入对应输出地址。默认结果使用holding寄存器：OK=1、NG=2；coil类型省略value时使用OK=1、NG=0，也可在节点中明确设置固定value。

要按具体信号放行流程，可在触发节点的参数中设置下列内容，再在控制台将 `plc-1` 的 DI3 打开：

```json
{"deviceId":"plc-1","function":"discrete","address":3,"requireValue":1,"timeoutMs":60000,"pollMs":50}
```

显式设置 `requireValue` 后，流程始终检查该表值；自动触发和“触发一件”不会绕过条件。可以改为 `holding` / `input` / `coil` 测试对应信号。

## 场景与故障

工件场景支持交替示范、始终合格、始终超差、缺件。交替示范中每第5件直径23mm，其余20mm；默认判定范围19..21mm。缺件或光照不足会使测量报故障，在保存前停止，所以不会产生一条伪造的检测成功记录。

连接开关可模拟设备断线；虚拟急停会立即停止所有虚拟轴，并使检测流程在后续设备检查时故障。即使在延时节点内先急停/断线再恢复，本轮流程也会保持中断，必须手动重新启动。重置只在流程停止且已解除急停时可用，会清空虚拟设备位置、亮度、信号、触发队列和调试模式；不会删除检测数据库。

控制台状态仅存在于本次进程中，不保存到 `.ivproj`；保存、重复运行保留当前状态，新建/打开工程或点击重置恢复初始状态。

这是恒速运动、合成图像和信号表组成的软件仿真，用于验证业务流程和界面联动；未模拟伺服动力学、脉冲精度、电气时序或硬件安全联锁。虚拟 PLC 是进程内共享设备，未作为独立 Modbus TCP 服务器对外监听。
