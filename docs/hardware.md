## 有状态虚拟硬件

主界面的仿真控制台与检测工作线程共享 `SimulationPlant`；各设备按 ID 隔离，操作不会连接真实硬件。同 ID、同类别的设备重新配置时保留状态。模拟状态不写入检测工程；重置只在流程停止时进行。

每个运动设备有 4 轴，初始使能、已回零，位置与目标为 0，默认速度 25 mm/s，流程节点速度大于 0 且不超过 1000 mm/s，软限位 -100..100 mm。恒速模型使用单调时钟推进，关闭控制台后运动仍会推进。可使能、移动、回零、停止、手动改位置；不是驱动器电气或机械模型。流程运动节点等待到位，停止、故障、关闭会冻结虚拟轴。

每台光源有 4 通道，亮度 0..255，默认打开且亮度 80。`light` 节点实际改变亮度和开关，关闭或亮度过低会使图像无法通过阈值分析并触发流程故障。控制台手动接管只对模拟运动、光源节点生效，适合保留当前调试值运行检测。

每台模拟 PLC/I/O 有 64 个 holding、64 个 input 寄存器，以及 16 个 coil、16 个 discrete 信号，地址均从 0 开始。控制台可强制输入；输出节点只写 holding（`register` 或 `holding`）与 coil。显式 `requireValue` 必须满足真实表值；没有显式条件时，默认自动触发，可关闭自动触发后逐件排队，或使用 DI0。急停与断线会使后续模拟操作失败，解除后需手动重新启动。

## 模拟相机

输出 RGB32 图像，深色背景上绘制亮色圆形工件，无文字或额外亮色标记干扰阈值检测。默认亮度 80、标定 20 px/mm 时，正常直径为 400 px；序号为 5 的正整数倍时为 460 px，位置按序号产生小幅确定性偏移。默认应测得约 20 mm 与 23 mm。控制台可强制正常、NG、无工件或恢复交替工件模式。

图像受虚拟平台 XY、光源 CH1 和工程 `pixelsPerMm` 影响。相机设备的 `parameters` 可明确配置 `motionDeviceId`、`lightDeviceId`、`lightChannel`（0..3）；未指定时选择第一台同类别虚拟设备。显式引用无效或断线时返回错误，不会静默改选其他设备。`SimulatedCamera::capture()` 保留独立默认场景接口，方便无设备网关的像素测试。网关图像分辨率允许每轴 16..8192，且最多 16 兆像素；工程配置至少 64×64。独立 `SimulatedCamera` 接口为兼容原有调用保留最多 64 兆像素。小图像按可容纳范围缩小工件。

## Modbus TCP

`ModbusTcpClient` 通过 Qt Network 的 `QTcpSocket` 实现协议，无 Qt SerialBus 依赖。支持 01 读线圈、02 读离散输入、03 读保持寄存器、04 读输入寄存器、05 写单线圈、06 写单寄存器。寄存器按大端序解析，位按每字节最低位优先解析。寄存器单次最多 125 个，位单次最多 2000 个；地址范围越界会被拒绝。

每个请求生成独立事务号并验证响应的事务号、协议号、长度、单元 ID、功能码、字节数和写操作回显；异常功能码返回对应异常错误。报文分片会累积读取，整个请求共用超时预算。超时或不合法响应关闭连接，避免延迟报文串入后续事务。标准设备异常返回错误但保留连接。默认端口 502，单元 ID 1（配置范围 0..255），默认超时 1000 ms（配置范围 1..60000 ms）。

设备示例：

```json
{
  "id": "plc1", "category": "plc", "model": "Schneider TM221CE16T",
  "backend": "modbus-tcp", "host": "192.168.1.10", "port": 502,
  "unitId": 1, "parameters": { "timeoutMs": 1000 }
}
```

地址参数是协议中的 **零起始地址**，不会自动将 40001 转换成 0。实际地址、字节/字序、线圈含义与联锁必须按项目和控制器手册配置。

触发节点读取地址，并可检查 `requireValue`。运行管线通过明确的就绪状态轮询不满足条件的触发，支持 `pollMs` 与 `timeoutMs`；通信错误直接故障，详见 `docs/runtime.md`。单独调用网关 `execute()` 只读取一次，不满足条件时返回错误：

```json
{
  "id": "wait-part", "type": "trigger", "title": "工件到位", "enabled": true,
  "parameters": { "deviceId": "plc1", "function": "holding", "address": 0, "requireValue": 1 }
}
```

触发功能可选 `holding`（03，默认）、`input`（04）、`coil`（01）、`discrete`（02）。输出节点写入一次：

```json
{
  "id": "result-out", "type": "output", "title": "结果输出", "enabled": true,
  "parameters": { "deviceId": "plc1", "function": "coil", "address": 1, "value": 1 }
}
```

输出功能可选 `register` / `holding`（06，默认 register，值 0..65535）或 `coil`（05，值 0 或 1）。省略 `deviceId` 时选择第一个匹配类别的设备，多设备项目应显式指定。触发与输出只接受 PLC/I/O；运动与光源目前只接受模拟后端。模拟触发读取共享虚拟信号或触发队列，不产生真实网络读写。

## MVS SDK 构建钩子

`IVS_WITH_MVS` 默认关闭。启用后，CMake 只查找用户安装的 `MvCameraControl.h` 及匹配的 MvCameraControl 库、定义编译宏并校验头文件可用；不会下载、复制或分发厂商 SDK。可配置 `IVS_MVS_ROOT`，或显式配置 `IVS_MVS_INCLUDE_DIR` 与 `IVS_MVS_LIBRARY`。

```sh
cmake -S . -B build/mvs -DIVS_WITH_MVS=ON -DIVS_MVS_ROOT=/path/to/MVS
```

此版本的 `HikMvsCamera` 是明确返回不可用原因的扩展入口，**没有实现枚举、打开、曝光、触发、像素格式转换或图像采集**。即使 SDK 构建钩子通过，`mvs` 后端依然拒绝配置。后续接入应在合法安装和授权的目标平台上实现并验证采集、断线恢复和资源释放，然后再更新适配状态。

## 实机验收边界

本次自动化验证使用本机真实 TCP 连接与受控 Modbus 服务端覆盖读写帧、分片、异常与错误报文；未连接上表实物。设备寄存器映射、运动命令、光源亮度、硬触发和安全联锁都需要项目级验证。界面“停止”取消软件后续节点并停止虚拟轴，不能替代真实控制器急停。
