# 检测执行与生命周期

`PipelineWorker` 是可移动到 `QThread` 的 `QObject`。计时器是其子对象，会随工作对象移动；设备网关、TCP 连接、数据仓库和 SQL 连接只在 `start()` 所在的工作线程创建和释放。调用方应在启动前通过 `setSimulationPlant(shared_ptr<SimulationPlant>)` 注入控制台共享的虚拟硬件，再完成 `moveToThread()`，通过队列连接调用启动、停止，在退出线程前调用 `shutdown()`。注入必须发生在工作对象所属线程且处于停止状态；运行中、跨线程或关闭后调用会返回 false。未注入时工作对象自建独立仿真状态。重复启动运行中的任务会记录警告；已关闭的工作对象不会重新启动。

启动首先执行 `validateProject()`，验证采集、测量、判定和保存节点各有且只有一个，且顺序正确，再接入设备与数据库。无效工程不会创建检测数据库。设备连接、数据库打开、图像采集、分析、PNG 写入、记录保存或输出失败都会停止后续节点，发送错误日志与 `fault` 状态。

## 节点调度与节拍

每个启用节点在独立的事件循环轮次执行，不使用阻塞休眠。`delay.ms` 使用单次计时器；同一时刻只有一个检测周期。周期从开始计时，执行完后等待 `max(0, cycleMs - 已耗时)`，因此正常节拍按周期间隔维持；执行超过节拍时紧接下一个周期，不并发补跑。工程最小节拍 100 ms，正常连续运行的结果频率不超过每秒 10 条。

当前周期只持有一帧图像和一份结果，界面仅在保存成功后收到 `resultReady`，其中 `record.id` 已由真实数据库返回。`capture` 按可选 `deviceId` 选择相机；引用运动、光源或不存在的设备会失败。`inspect` 调用实际阈值与几何分析，依据 `pixelsPerMm` 生成毫米尺寸和偏移；`judge` 根据配置的闭区间上下限生成 OK 或 NG。

`store` 先按策略保存图像，再写检测记录。若图像失败或数据库拒绝插入，不会发出已保存结果；该周期刚创建但尚未入库的图像会被删除。已经入库的记录不能因随后输出失败而撤销；输出失败会进入故障态并保留该记录。`cycleFinished` 只在全部启用节点执行完成后发出。单次运行完成后进入 `stopped`。

`output` 未指定 `value` 时，将已保存结果转换成寄存器值：OK=1、NG=2、ERROR=3。未指定值的 coil 表示是否合格：OK=1、NG/ERROR=0。显式 `value` 按原值写入，coil 只接受 0 或 1。

## 虚拟设备与运动等待

`DeviceGateway` 与控制台持有同一线程安全的 `SimulationPlant`。启动同步设备定义并设置工程 `pixelsPerMm`，保留相同 ID/类别设备的手动位置、亮度、连接状态和信号表。每个节点执行前检查虚拟急停及连接状态；虚拟运动完成前不会采集图像。急停断言、在线设备断线、重置都会递增不可清除的中断计数；即使在延时期间解除急停或恢复连接，当前运行也会在下一个节点边界进入故障，必须明确重新启动。启动时以同一状态快照检查当前故障并记录计数，在设备连接和数据库初始化后再次确认；已有故障不能靠启动后立即清除而绕过。未配置虚拟设备的真实 Modbus 网关不受仿真急停影响。

`move` 只下发一次，然后每 20 ms 读取 `motionReady()`；当前轴仍在运动时让出事件循环。轴禁用、断线、故障或急停会立即失败；非手动接管模式下，控制台停止或改动目标导致未到达节点请求的位置也会故障；超过 `timeoutMs`（默认 10000，范围 1..60000）会停止轴并故障。参数为 `axis`（默认 0，0..3）、`position`（默认 0，毫米，受软限位约束）、`speed`（默认 25，大于 0 且不超过 1000 的有限数，毫米/秒）。必须使用 JSON 数字，字符串不会被自动转换。

`light` 设置指定 `channel`（默认 0，0..3）的 `brightness`（默认 80，0..255）与 `enabled`（默认 true，JSON 布尔值）。手动接管打开时，运动和光源节点保留控制台值；运动节点仍检查轴状态并等待控制台发起的运动完成。模拟输出实际写入所选设备的 holding 寄存器或 coil，供后续触发和控制台读取。

## SCARA 机械臂节点

新建工程在设备列表末尾包含 `robot-1`（`robot` 类别、`simulated` 后端），原有相机、平台、PLC 顺序不变。已有工程可以添加该类别；真实机器人 SDK 尚未接入。机械臂与光源/平台使用同一 `SimulationPlant`，控制台显示的 TCP、夹爪、手持工件和料箱计数均为运行器实际修改的状态。

`robot_move` 是笛卡尔终点定位，参数 `x/y/z/r` 默认 `220/40/100/0`（毫米/度），`elbowPositive` 默认 true，`speedPercent` 默认 60、允许 1..100 的有限数字，`timeoutMs` 默认 30000、允许 1..60000 的整数。`deviceId` 省略时选择第一台机械臂；显式引用不存在、类别错误或非模拟后端会失败。运行前执行共享解析 IK 与关节限位校验，非法目标不会打开检测数据库。模型为 180/140 mm 两连杆、J1/J2 ±170°、J4 ±180°、Z 0..150 mm；执行采用关节空间同步插补，不能视为 TCP 直线轨迹、真实伺服动力学或碰撞检测。

`robot_grip` 的 `closed` 为 JSON 布尔值，默认 true。关闭夹爪时，TCP 必须位于料位附近才能实际抓到工件；手持工件跟随 TCP，张开时按实际释放位置更新 OK/NG 计数。机器人定位和夹爪节点可位于采集前或后；采集→测量→判定→保存的必需顺序保持不变。

`robot_sort` 最多一个且必须位于 `store` 之后。它只能使用本周期已经提交记录的 OK/NG 结果，不接受 `outcome` 或其他结果覆盖参数。默认 `speedPercent=60`、`timeoutMs=60000`、`restock=false`；显式 `restock=true` 在下发分拣前补充一件虚拟工件，手持工件时补料会报错。完整程序执行料位上方→下降→夹取→抬升→结果料箱上方→下降→释放→抬升，实际释放才增加对应计数。

运行器对每个机械臂节点只下发一次命令，记录设备与命令序号，每 20 ms 非阻塞检查 `robotReady()`。只有该确切序号完成才进入下一节点；停止、改目标、禁用、断线、急停或超时不会被当作到位。平台/光源的“手动接管”不影响机械臂节点，机械臂手动发令在流程运行期间由界面锁定，停止和急停仍可使用。停止、故障和关闭取消机器人剩余程序并冻结当前关节状态，解除联锁后必须明确重新启动。

`resultReady` 仍在 `store` 提交后立即发出，因此分拣期间可能已经显示该条记录；`cycleFinished` 必须等待分拣和全部后续启用节点完成。分拣中停止或故障会保留已提交记录，并且不会声称该周期已完成。

## 触发等待

模拟触发默认自动就绪。关闭自动触发后，无 `requireValue` 的节点消耗一次排队触发，或等待设备 DI0 为真。显式 `requireValue` 始终检查所选信号表的当前值，自动触发开关不会绕过这个条件，读取也不会消耗排队触发。真实 Modbus 触发使用 `DeviceGateway::triggerReady()` 的明确状态 `Ready`、`Waiting`、`Failed`，不根据错误字符串判断。`requireValue` 未满足时，工作线程按 `pollMs`（默认 50，范围 1..1000）再次读取；达到 `timeoutMs`（默认 1000，范围 1..60000）后报故障。通信异常会直接故障。可在触发节点参数里配置：

```json
{ "deviceId": "plc1", "function": "holding", "address": 0,
  "requireValue": 1, "pollMs": 50, "timeoutMs": 3000 }
```

单次 Modbus 读写受设备的通信超时约束，轮询等待受节点的超时约束。停止在工作线程处理到停止请求后取消后续节点；正在执行的同步 SDK、文件、SQL 或网络操作须返回后才能处理队列中的停止请求。

## 停止与关闭

`stop()` 停止计时器、使待执行回调的代次令牌失效、清空尚未保存的周期数据，并在工作线程销毁 SQL 和设备对象。停止发生在 `store` 之前时不会写入该周期记录。停止发生在提交之后时，已提交记录保留。`shutdown()` 同样取消待执行工作，并进入 `idle`，供线程退出清理使用。线程应自然退出，不使用 `terminate()`。

停止、故障和关闭会将全部虚拟轴停在当前位置，清除运动状态，并取消后续回调。它们不代表真实硬件急停；同步操作不会在执行中被强制中断。

## 图像留存

策略 `none` 不保存图像；`ng` 保存 NG/ERROR；`all` 保存每一帧；`sample` 保存每个运行中序号为 10 的整数倍的帧。图像保存到工作空间的 `data/images/ivs-managed/ivs-<32位UUID>.png`，使用 `QSaveFile` 原子提交。工作空间解析为规范路径，图像目录的各级组成不能是符号链接或普通文件。

清理仅针对该专用目录内名称符合 `ivs-<32位小写十六进制>.png` 的普通文件，不读取数据库里的任意路径用于删除，不递归跟随目录或符号链接，不删除其他名称的文件。超过保留天数的文件先被清理，然后按修改时间从旧到新清理到容量配额以内，当前周期的新图像受保护。清理失败或当前图像本身超出配额会报故障。

检测记录中的 `imagePath` 保存为相对工作空间的 `data/images/ivs-managed/...png` 路径，整体移动工作空间及其数据库后仍能定位图像；界面读取时应以当前工作空间解析。历史记录中的图像路径可能因到期或配额清理而失效；记录和测量数据仍保留，界面应提示文件缺失。

## 自动化覆盖

`tst_pipeline` 在真实 SQLite 和合成像素上验证单件 20 mm、第五件 23 mm NG、先提交后发信号、非法顺序、停止/关闭期间取消延时、数据库目录和插入失败、图像保存失败、管理目录与配额、相机引用校验，以及工作对象移动到独立线程后的干净资源释放。新增覆盖共享状态手动触发、实际输出、运动等待与超时、光源变暗导致分析故障，以及停止/关闭/急停/断线冻结虚拟运动且不保存后续记录、控制台中断或改目标的到位校验。机械臂覆盖共享状态到位等待与夹取、确切命令序号、实际 OK/NG 释放计数、保存后停止/关闭/改令/禁用/急停/断线保留记录且不完成周期、超时与非法配置不保存记录。设备协议的分片、异常、错误帧与超时由 `tst_devices` 验证；厂商实机验收另见硬件文档。
