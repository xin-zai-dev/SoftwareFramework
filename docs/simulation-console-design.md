# 有状态虚拟硬件与仿真控制台

用户要求直接完善运动、光源、PLC/I/O仿真，并提供可视化控制台，在无硬件环境测试完整流程。沿用Qt6/C++17/CMake和当前项目目录。

## 选择与边界

采用应用内共享、线程安全的SimulationPlant，而不是新增独立网络服务或外部仿真器。它不连接任何真实硬件；现有真实ModbusTCP路径保持独立。虚拟运动为恒速位置模型，不模拟驱动器电气/力学，也不宣称等效实际控制卡。状态不作为检测工程配置自动持久化，以免残留触发信号影响下次启动。

## 行为

- 按设备ID隔离状态：每个运动设备4轴、光源4通道、PLC/I/O各64个holding/input寄存器与16个coil/discrete信号。
- 轴有使能、当前位置、目标、速度、软限位、运动和回零状态。使用单调时钟推进，关闭控制台也能完成运动。停止/故障/关闭必须取消运动。
- 光源等级0..255，默认80保持既有图像曝光；CH1控制默认相机图像。暗光/关灯会使图像无法测量并报告故障。
- 相机图像受第一台虚拟平台XY与第一台光源CH1影响，可通过camera.parameters的motionDeviceId/lightDeviceId/lightChannel显式选择；scene标定使用工程pixelsPerMm。
- 控制台“手动接管”仅对虚拟运动/光源生效；开启后节点保留当前控制台值，关闭后节点按参数下发。
- 自动触发默认打开，兼容既有示例；关闭后可排队“触发一件”，或用DI0作为默认到位条件。显式requireValue始终按信号表检查，不被自动触发绕过。hold/input/coil/discrete与真实Modbus术语一致；仅仿真允许强制输入。
- 输出节点必须实际更新所选虚拟设备的寄存器或线圈，默认OK=1、NG=2；不虚构实际分拣机构。
- 仿真急停、断线、强制NG/无工件用于测试故障与恢复；解除后必须手动重新启动流程。
- 控制台显示当前值、待触发计数和虚拟设备连接状态。运行时可改变输入和亮度；运行中禁止重置整套状态。

## 接口与集成

SimulationPlant.h为共享契约，console和worker持有同一shared_ptr。DeviceGateway默认独立创建plant以兼容现有调用；MainWindow注入共享plant。PipelineWorker增加注入接口、异步运动等待和取消，不在GUI线程阻塞。

主界面增加“仿真控制台”页，运行时仍可访问，仅操作simulated设备。设备定义加载/新建时同步，启动时保留同ID同类别的手动状态。所有错误必须显示，不默默回退到第一台设备。

## 验证

先验证失败测试再实现：确定性时钟轴运动/限位/急停、光源图像像素变化、信号类型/地址、触发队列、多设备隔离；再测网关/执行器等待人工触发、运动完成、输出值、低光故障、停止与关闭。UI自动化验证真实控件修改共享状态。最终完整CTest、实际窗口截图、无硬件工程端到端和当前平台发布包验证。
